# Pulsar Trigger — Code Audit (2026-06-18)

Read-only audit at **v0.493.0 / versionCode 504**. Scope: full codebase —
Android/Kotlin app (`android/`, ~42.7k LOC Kotlin) + ESP32/C++ firmware
(`firmware/`, ~1.8k LOC). Read `CLAUDE.md`, `docs/*.md` (incl.
`parked-audit-items.md`) first; documented/intentional choices are **not**
flagged as bugs. No code was changed.

Tooling run: Android `lint` + `testDebugUnitTest`; firmware `pio check`
(cppcheck) + `pio test -e native`. Summary in the appendix.

---

## Executive summary

The project is in **good health**. Architecture is disciplined for its size:
the five-transport abstraction holds (four `CameraTransport` impls funnel
through `CanonRunner` + a debug mutual-exclusion assertion; ESP32 + simulator
are explicit branches), the shared `PtpClient`/`PtpWire` split is clean, run
loops are transport-agnostic, and the firmware `triggers_tick()` is genuinely
non-blocking. Security hygiene is strong: no committed secrets (keystore
gitignored), CCAPI credentials encrypted at rest, hand-rolled RFC 7616 digest
auth is correct, cleartext is gated to private IPs, BLE writes require an
encrypted/bonded link, and the `.pulsar` import path is size-capped and
schema-validated. All 27 firmware tests and 21 Android test suites pass;
cppcheck reports 0 high/0 medium.

**Fix first (in priority order):**

1. **PTP wire reads allocate from an unbounded, untrusted length field** →
   OOM/crash, reachable over the LAN during a PTP/IP session (incl. the
   pre-confirmation handshake). The single genuinely security-relevant finding.
2. **The 5th transport (PTP/IP) was added but never propagated into ~7
   "which other transports are active" guard predicates** (and Canon BLE is
   missing from two). Violates the documented mutual-exclusion-symmetry
   invariant; latent state-clobber / transport-steal. Mechanical fix.
3. **42 untranslated strings** (Manage Devices + GATT Explorer + dev options)
   break the project's own "all 6 locales" rule — and **CI never runs lint**,
   which is why they (and a widget crash-on-old-Android bug) slipped through.
4. **Widget initial/preview layout references an API-31 system color** with
   `minSdk 26` → `NotFoundException` on the widget host for Android 8–11.
5. **Credential-encryption library pinned to an alpha** (`security-crypto:1.1.0-alpha06`).

## Findings by severity

### High

#### H1 · Unbounded allocation from untrusted PTP length field (OOM / DoS)
`ptp/PtpIpWire.kt:166-167`, `ptp/PtpIpWire.kt:308-309`, `ptp/BulkPtpWire.kt:105`

All three wire-read paths size a buffer directly from a length field supplied
by the remote device, with **no lower or upper bound**:

```kotlin
// PtpIpWire.recvPacket()           ← every packet on the cmd socket
val bodyLen = length - 8            // length = u32 read from the TCP socket
val out = ByteArray(bodyLen)        // length≈0x7FFFFFFF → ~2 GB alloc → OOM
```
```kotlin
// BulkPtpWire.readData()
val out = ByteArray(declared - 12)  // declared < 12 → NegativeArraySizeException
```

A crafted (or buggy) responder sending a header with a huge `length`/`declared`
triggers an out-of-memory crash; `length < 8` / `declared < 12` throws
`NegativeArraySizeException`. For PTP/IP this is **network-reachable** by any
host the app connects to on port 15740 — including a rogue host reached via
mDNS/ARP spoofing on the shared Wi-Fi, and crucially **`recvPacketRaw()` runs
during `connect()` before the user confirms anything on the camera**, so the
prompt-gate offers no protection. USB (`BulkPtpWire`) is lower-exposure
(physical access) but the same defect. Maps to CWE-789 (Memory Allocation with
Excessive Size Value) / improper length validation.

**Fix (S):** before allocating, validate against a sane cap (e.g. a few MB —
larger than any DeviceInfo or live-view JPEG Pulsar reads) and reject with
`PtpProtocolException` on `length < 8` / `declared < 12` or `> MAX`. Apply at
all three sites; consider a shared `private fun safeBodyLen(declared, max)`.

### Medium

#### M1 · PTP/IP (5th transport) missing from transport-ownership guards
`viewmodel/PulsarViewModel.kt` — `disconnectCanonCcapi:1559`, `disconnectPtp:1848`,
`disconnectCanonBle:1829`, `idleAcrossOtherTransports:776`, the two init
collectors `:1048` & `:1070`, and `stopFlow:2407`

The run-loop dispatch (`activeCameraTransport()`, `:2354`) correctly enumerates
all four `CameraTransport` impls and even asserts mutual exclusion in debug. But
the **ownership / idle predicates that gate `_connected`/`_status` and
auto-reconnect were not updated when PTP/IP became the 5th transport**, and two
predate Canon BLE (the 4th):

| Site | Checks | Missing |
|---|---|---|
| `disconnectPtpIp:590` | BLE, sim, CCAPI, USB-PTP, Canon-BLE | — (complete) |
| `disconnectCanonCcapi:1559` | BLE, sim, USB-PTP | **Canon-BLE, PTP/IP** |
| `disconnectPtp:1848` | BLE, sim, CCAPI | **Canon-BLE, PTP/IP** |
| `disconnectCanonBle:1829` | BLE, sim, CCAPI, USB-PTP | **PTP/IP** |
| `idleAcrossOtherTransports:776` | BLE, sim, CCAPI, Canon-BLE | **PTP/IP** |
| `bleController.connected.collect:1048` | CCAPI, USB-PTP, Canon-BLE | **PTP/IP** |
| `bleController.status.collect:1070` | sim, CCAPI, USB-PTP, Canon-BLE | **PTP/IP** |
| `stopFlow:2407` | sim, CCAPI, USB-PTP, Canon-BLE | **PTP/IP** |

Why it matters: this is precisely the failure mode the project's own
`parked-audit-items.md` (R3) names — *"a future flag added and forgotten in one
branch."* The most concerning are the two `init` collectors: while connected via
PTP/IP, a stale `BleController` emission would fall through and clobber
`_connected`/`_status` (the v0.252/v0.253 class of bug CLAUDE.md documents).
`idleAcrossOtherTransports` omitting PTP/IP means the USB auto-reconnect
collector could steal a PTP/IP session. Most paths are *masked today* by
mutual-exclusion teardown ordering (the new transport's StateFlow is still null
during teardown), so this is **latent rather than a reproducible user bug** —
but it's a real invariant violation and a landmine for the next transport.

**Fix (S):** extract the predicate once and reuse it everywhere:
`private fun otherTransportsIdle(except: …) = …` covering all five siblings;
or a `shouldReleaseConnectionState()` helper the disconnects call. Net ~15 lines,
no behaviour change in the masked paths.

#### M2 · 42 strings untranslated — violates the all-6-locales rule
`app/src/main/res/values/strings.xml` (lint `MissingTranslation`, 42 keys)

New strings were added to `values/strings.xml` without the de/pt/ja/fr/es/zh
copies CLAUDE.md mandates. They cluster in two recent features:
`section_devices` + `devices_*` (**Manage Devices — user-facing**),
`gatt_explorer_*` (debug-gated, lower impact), and `about_debug_mode_*` /
`about_developer_options` / `section_gatt_explorer*`. On a non-English device
these render in English. Several of these keys are *also* unused (see M4), i.e.
dead strings that still trip the build's lint.

**Fix (M):** add the 6-locale translations for the Manage-Devices and
developer-options keys; delete the ones that are also unused.

#### M3 · Widget initial/preview layout crashes on Android 8–11
`app/src/main/res/layout/widget_initial_layout.xml:8` (lint `NewApi`)

`android:background="@android:color/system_neutral1_900"` requires API 31, but
`minSdk = 26` and this layout is wired as **both** `initialLayout` and
`previewLayout` (`res/xml/dashboard_widget_info.xml:3,12`). On API 26–30 the
widget host (launcher process) inflates a reference to a non-existent resource →
`Resources.NotFoundException` — the placeholder shown before Glance renders, and
the picker preview, fail on every pre-12 device.

**Fix (S):** replace with a literal `#1B1C1A`-style color or a `@color/` defined
in `values/` (with an optional `values-v31/` override for the dynamic color).
While there, externalize the two hardcoded strings (`HardcodedText` lint).

#### M4 · ~99 unused string resources
`app/src/main/res/values/strings.xml` (lint `UnusedResources`, 99)

Genuine dead strings, many from retired UI: `btn_start_astro`/`btn_stop_astro`,
`card_summary`, `cd_expand`/`cd_collapse` (the accordion removed in v0.483),
the `canon_setup_step_*` block, `label_astro_formula`, several `gatt_explorer_*`
(also untranslated). Confirmed unused by lint's resource graph.

**Fix (S):** delete after a quick `grep R.string.<name>` confirm per key (lint is
reliable here, but the project rule is "confirm with grep").

#### M5 · Lint is not run in CI — errors never block a release
`.github/workflows/android.yml:51,57`

CI runs `./gradlew test` then `./gradlew assembleRelease` — **never `lint`**.
`assembleRelease` does not trigger `lintRelease`, so the 48 lint *errors*
(MissingTranslation, NewApi/M3, AppLinkUrlError, MissingPermission) never fail
the pipeline. This is the root cause that let M2 and M3 ship. Locally
`./gradlew lint` already fails (abortOnError defaults true).

**Fix (S):** add a `./gradlew lintRelease` (or `lintDebug`) step to
`android.yml`, or at minimum gate on the translation/`NewApi` checks.

#### M6 · Credential encryption pinned to an alpha library
`app/build.gradle.kts:90`

`androidx.security:security-crypto:1.1.0-alpha06` backs the
`EncryptedSharedPreferences` that store CCAPI digest credentials. Shipping an
**alpha** crypto dependency in the component that protects secrets is avoidable
risk; `1.1.0` stable is available (lint `GradleDependency`).

**Fix (S):** bump to `1.1.0` and smoke-test the existing v1→v2 cred migration
(`buildCanonCredsPrefs`, `PulsarViewModel.kt:94`).

### Low

- **L1 · `_status` mixes atomic and non-atomic writers.**
  `transport/CanonRunner.kt` writes the shared `_status` flow with non-atomic
  `status.value = status.value?.copy(...)` (12 sites) while the CCAPI poll uses
  atomic `_status.update { }` (`PulsarViewModel.applyCanonPollUpdate:1504`).
  During a CCAPI bulb run the run loop's read-modify-write can clobber a battery/
  shot-count poll update (transient, self-heals next poll). Switch CanonRunner to
  `status.update { }`. (S)
- **L2 · `MissingPermission` lint, suppressed-by-design but unannotated.**
  `viewmodel/PulsarViewModel.kt:1160` (`device.name`) and
  `ui/screens/GattExplorerScreen.kt:264` (`adapter.bondedDevices`) are reached
  only after the app's permission gate, but lint can't see that and errors.
  Add explicit `@SuppressLint("MissingPermission")` with a justifying comment. (S)
- **L3 · Over-broad `.pulsar` intent filter.** `AndroidManifest.xml:61-67` declares
  `mimeType="application/octet-stream"` + `pathPattern` but **no scheme**, so
  `pathPattern` is ignored and the app registers as a handler for *all*
  octet-stream opens (the `content`-scheme filter at :68-75 already covers the
  real case). Source of the 3 `AppLinkUrlError` lint errors. Drop the
  octet-stream filter or give it a scheme. (S)
- **L4 · Dependency staleness.** Nordic BLE `2.7.5`→`2.11.0`, MapLibre
  `11.8.0`→`13.3.0`, plus the AndroidX cluster (lint `NewerVersionAvailable`/
  `GradleDependency`). No known critical CVE in the pinned versions; MapLibre is
  the largest gap and ties into the now-completed annotation-API migration.
  Modernization, not urgent. (M)
- **L5 · `BulkPtpWire.readData` silent truncation.** On a short device read the
  loop `break`s and returns a zero-padded buffer with no error
  (`ptp/BulkPtpWire.kt:109-115`). Benign today (callers tolerate), but couple it
  with the H1 cap fix. (S)
- **L6 · Network JSON uses throwing accessors.** `astro/AstroDashboardData.kt`
  mixes throwing `getJSON*/getDouble/getInt` (~43) with safe `opt*` (~45);
  relies on outer `try`/`runCatching` (18) to turn an Open-Meteo schema change
  into the dashboard error state. Works, but prefer `opt*` + explicit defaults at
  the leaves so one missing field doesn't blank the whole panel. *(Low /
  partially unverified — outer guards appear to cover the fetch.)* (M)
- **L7 · `UseKtx` (49), `PluralsCandidate` (23), `Typos` (8)** lint nits — purely
  cosmetic/modernization. (S each)

## Per-area notes

1. **Code quality & smells.** Clean for the size. `PulsarViewModel` (3,291 LOC)
   is large but **not** a god object: per-transport leaf logic is pushed into
   `…PulsarViewModelExt.kt` extensions, state is well-encapsulated, and KDoc is
   thorough. Largest UI files (`SharedSections` 2,049, `CustomFlowScreen` 1,890)
   are long-but-flat Compose, acceptable. Only **1 TODO/marker** in the whole
   tree — exceptional discipline. Worst smell is the repeated transport-guard
   predicate (M1), which begs a helper.
2. **Dead / unused code.** ~99 unused string resources (M4) and the dead strings
   that are also untranslated (M2) are the real debt. Code-level dead functions:
   cppcheck's 37 `unusedFunction` hits are **false positives** (cross-TU entry
   points called from `main.cpp`/`ble_server.cpp`). The previously-flagged
   fallback widget composables and `DashReadoutRow`/`ReadoutTile` were already
   purged in v0.491.
3. **Unwired functions.** None of substance. The `.pulsar` VIEW/SEND intents
   *are* wired (`MainActivity.readImportIntent` → `importSettingsJson`); the only
   wiring wart is the over-broad octet-stream filter (L3).
4. **Concurrency / races.** Strong overall — jobs are tracked and
   `cancelAndJoin`-ed, GATT callbacks documented as off-main and only touch
   thread-safe `StateFlow` setters, `NonCancellable` brackets guard shutter
   release. Issues: the latent guard cluster (M1) and the `_status` writer mix
   (L1). The known ramp-stall (`project_ramp_bug`, HELD pending a device diag
   dump) lives in this area — not re-flagged, per its tracked status.
5. **Security.** Best area. No committed secrets; CCAPI creds encrypted (alpha
   lib — M6); RFC 7616 digest correct (SecureRandom cnonce, MD5/SHA-256/sess);
   cleartext gated to RFC1918 via `isPrivateIpv4`; BLE writes + OTA require
   `WRITE_ENCRYPTED` + bonding; firmware TLV reader fully bounds-checks declared
   length and every value; `.pulsar` import is 1 MB-capped + schema-validated;
   no NDA Canon-SDK text in-repo. The one real defect is H1 (PTP length
   validation). Exported components (MainActivity, widget receiver/config) are
   appropriate for their roles.
6. **Dependency health.** Moderately behind (L4); no flagged CVEs. The alpha
   crypto pin (M6) is the only one with a security dimension.
7. **Architecture & design.** The intended structure holds: `CameraTransport` /
   `CanonRunner` / `PtpWire` abstractions are respected, `AstroDashboardContent`
   is now a single shared composable (v0.493, used by both the Astro tab and the
   planner), `astro/NightModel` is shared by dial + widget. No layering inversion
   spotted (business logic stays out of Compose). M1 is the one crack in the
   five-transport symmetry.
8. **Performance.** Firmware `triggers_tick()` confirmed non-blocking
   (`millis()` comparisons, wraparound-safe; the only blocking is
   `camera_shutter` via `interruptible_delay`, which yields every 10 ms and
   checks `STATE_IDLE`). Compose recomposition concerns are the parked O1 item
   (~1 Hz poll, below frame budget). No N+1 or main-thread I/O found (HTTP on
   `Dispatchers.IO`).
9. **Error handling & logging.** Generally good — `runCatching` blocks are around
   genuinely best-effort wire writes (idempotent `stopBulb`), and the flow job
   correctly **rethrows `CancellationException`** before logging other throwables
   (`startFlow`, `:2265`). No swallowed cancellation found. Consistent `Log`/
   `CanonBleLog` usage; failures surface to per-transport error flows.
10. **Correctness / boundaries.** `when` over the `FlowStep` sealed type is
    exhaustive at every site; clamping is consistent (`coerceAtLeast`/`coerceIn`
    on every setter, firmware `clamp_u32`/`clamp_u16`). Boundary handling solid
    except the PTP length fields (H1).
11. **Testing.** Good breadth on the testable core: astro calculators
    (`AstroCalculatorTest`, `MoonPhaseTest`, `BestPhotoWindowsTest`,
    `WeatherCodeTest`, `DashboardStateTest`, `AstroExposureTest`), BLE parsing
    (`StatusFrameParseTest`, `DeviceInfoParseTest`, `CommandBuilderTest`), the run
    loop (`CanonRunnerTest` + `FakeTransport`), models, and firmware
    (`test_protocol`, `test_triggers`). **Gaps:** the PTP `PtpClient`/wire parsing
    is untested — and that's exactly where H1 lives; `CcapiClient` digest auth has
    no test; the VM mutual-exclusion/guard logic (M1) has no test. Adding a wire
    fuzz/bounds test would have caught H1.
12. **Documentation.** Unusually well-maintained — `docs/` tracks design and a
    living `parked-audit-items.md`; CLAUDE.md gotchas match the code. Minor drift:
    docs/comments still describe CCAPI as "Timelapse only / Phase 2," but the run
    loop now drives bulb/astro/dark-frame/ramp across all `CameraTransport` impls.
