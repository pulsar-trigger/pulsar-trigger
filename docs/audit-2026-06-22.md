## Findings by severity

### Medium

**M1 · Lint is failing — 5 errors abort `lintDebug`** · pre-existing
`lint-results-debug.xml`
- 3× `AppLinkUrlError` (manifest deep-link autoVerify), 2× `MissingPermission`
  at [GattExplorerScreen.kt:265](android/app/src/main/java/com/ehrocha/pulsar/ui/screens/GattExplorerScreen.kt#L265)
  (`adapter?.bondedDevices`). The BLE call is wrapped in
  `runCatching{}.getOrDefault(emptyList())`, so it's functionally safe — lint
  just doesn't recognise the guard. The AppLink errors may be real (a deep link
  that won't auto-verify).
- Why it matters: any CI lint step is red; real issues hide behind a failing gate.
- Fix: add `@SuppressLint("MissingPermission")` (justified — runCatching guards
  it) or an explicit `checkSelfPermission`; fix or `tools:ignore` the AppLink
  manifest entries. Effort: **S**.

**M2 · Restored theme / visual style doesn't apply until relaunch** · this session
[PulsarViewModel.importSettingsJson](android/app/src/main/java/com/ehrocha/pulsar/viewmodel/PulsarViewModel.kt) + [MainActivity.kt:179-190](android/app/src/main/java/com/ehrocha/pulsar/MainActivity.kt#L179)
- Import writes `visual_style`/`theme` to the `pulsar_ui` store, but
  `MainActivity` reads them once into a local `mutableStateOf` at startup, so a
  mid-session import shows "imported" while the theme is unchanged.
- Why it matters: silent partial effect; confusing on the "same phone" restore
  path (fine on a fresh install, which reads prefs at first launch).
- Fix: hoist visual-style/theme into an observable (StateFlow or a prefs
  listener) so import updates it live, or surface a "restart to apply theme"
  hint. Effort: **M**.

### Low

**L1 · `importSettingsJson` phase-2 can throw on a corrupt planner block** · this session
[PlannerManager.importAll](android/app/src/main/java/com/ehrocha/pulsar/planner/PlannerManager.kt) (called from phase 2)
- `importAll` reads `getInt("cloud_clear_threshold")` / `getLong("cache_interval_hours")`
  during phase 2, which the function comments promise is "pure assignment, can't
  throw." A hand-edited file with a non-numeric value would throw after presets/UI
  already applied → partially-restored state.
- Self-produced exports are always well-formed, so this only bites a tampered
  file (and the import UI catches it). Fix: use `optInt`/`optLong`, or parse the
  two ints in phase 1 alongside the other validation. Effort: **S**.

**L2 · Sub-screen legibility over the new backdrop** · this session · needs device
18 transparent Scaffolds (the v0.563 backdrop rollout)
- Screens whose content sits directly on the Scaffold body (not inside an opaque
  card) now render over the static starfield/board. Most wizards use opaque
  cards (backdrop shows only in gaps — intended), but plainer screens
  (calculators, logs) should be eyeballed for contrast. Add a faint scrim behind
  text-heavy bodies where needed. Effort: **S–M** per offender.

**L3 · Backdrop composed behind Menu/Scan too** · this session
[MainActivity.kt](android/app/src/main/java/com/ehrocha/pulsar/MainActivity.kt) (content Box)
- The global `SpaceField`/`PcbField` is in the content Box behind *every* screen;
  Menu and Scan paint their own opaque decoration over it, so it's drawn-but-hidden.
  Static draw, negligible cost, but it could be gated to non-Menu/Scan screens.
  Effort: **S**.

**L4 · Dead resources / lint backlog** · pre-existing
- 99 `UnusedResources`, 150 `LogNotTimber` (project uses `Log` by convention — noise),
  11 `AutoboxingStateCreation` (`mutableStateOf(0)` → `mutableIntStateOf`). Worth a
  one-off cleanup pass; none are correctness issues. Effort: **M**.

## Per-area notes

- **Settings backup (this session) — correct.** Two-phase parse/apply is sound;
  additive schema keeps old files importable; presets round-trip via
  `UserMode.toJson/fromJson` (schema-checked, `mapNotNull` drops bad entries);
  planner round-trips via the new `PlannerManager.exportAll/importAll` mirroring
  the on-disk keys. Restore-replaces-state semantics are consistent with the
  existing flow import. Only nits: M2, L1.
- **Preset cap + save-as-preset (this session) — correct.** Cap raised to 200
  (a safety bound, no UI hard-codes it); `upsertUserMode` now reports whether a
  new mode actually landed; `runUserModeNow` passes `delayMs` for Dark-frame/Ramp.
  `FlowStep↔Body` conversion verified as an exact inverse across all 5 modes.
- **Simulator gating (this session) — correct.** `onEsp` is now real-ESP-only,
  so the hardware Device/GPIO section is hidden in the simulator (matching how
  firmware OTA already gated). Removed the now-unused `simulatorActive` read.
- **Backdrop perf — clean.** `SpaceField(animated=false)` skips the frame loop
  and meteors; `FIELD_STARS`/`METEOR_LANES`/`DEEP_SKY` are module-level `val`s
  (computed once), so no per-composition allocation.
- **Photo-transfer / PTP content (post-audit, light review) — clean.**
  Object-walk safety cap at [PtpContent.kt:31](android/app/src/main/java/com/ehrocha/pulsar/ptp/PtpContent.kt#L31);
  downloads go through the H1-fix bounded receive length; `BitmapFactory.decodeByteArray`
  uses the already-received array size, not a remote-declared length. No
  unbounded-allocation of the class found by the 2026-06-18 audit.
- **Concurrency** — no new shared-state hazards in the churn. Backup file I/O
  runs on the SAF callback (main thread) as before; not introduced here.
